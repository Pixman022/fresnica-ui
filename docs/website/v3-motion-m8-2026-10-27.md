## Confirmed M8 visual issue
- At the reference's light-footer checkpoint around 87s, the reference dot-matrix wordmark is large and high-contrast. M7's FRESNICA dots were relatively pale and thin.
- Adjusted only the existing footer dot sampling `6px -> 5px` on desktop, dot-size variability, light-dot alpha/color, and light-footer background `#f7f8f7 -> #edf0ee`.
- The sampled alpha-bearing Canvas pixels (same 1600×1200 test) increased from **9,706 to 22,105**. This is a **visible dot coverage metric**, not a claim of 2.3x more DOM nodes or visual similarity.
- Before/after screenshots confirm clearer letterforms while retaining localized green plume, both footer theme modes and the existing dark-to-light controls.

## Test results
- Existing M6/M7 regression adapted to M8: **123/123 passed** across desktop 1440, 900, mobile 390, and Reduced Motion.
- Focused footer, mask and capsule QA: **31/31 passed**. No uncaught JS errors observed in these runs.
- 1600×1200 screenshot/scroll inspection at 8 reference checkpoints: no viewport horizontal overflow, no uncaught JS error, and navbar chapter labels tracked their sections.
- Headless Chromium performance sampling at a visible animated footer: in both M7 and M8, 91 requestAnimationFrame samples over approximately 1.5 seconds; mean frame separation approximately **16.67ms**, with no gaps >32ms in this environment. This short test is not a real-device performance guarantee.
- The approved Hero inline script remains identical, previous M5/M6/M7 scripts and information architecture remain unchanged.
- HTML remains `noindex,nofollow,noarchive`; no product availability or security claims changed.
