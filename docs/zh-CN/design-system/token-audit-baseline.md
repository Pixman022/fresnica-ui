# Token 审计基线

本文档记录设计 Token 审计的已评审基线。它是后续比较用的参照，不是永久锁定；如有明确的设计系统决策，仍可调整数值。

## 当前基线

- 记录日期：2026-09-11
- Git 基础：`main` 分支的 `1d5ffd5`，以及当前已评审的工作区设计改动
- 权威来源：`src/styles/variables.less` 与 `src/styles/themes/default.less`
- 运行时前缀：`--Fresnica-*`
- 浅色主色：`#00A875`
- 深色主色：`#00CA8A`
- 字体：Roboto、Noto Sans SC，再使用系统无衬线字体兜底
- 层级：通过语义表面和 1px 描边表达；阴影 Token 固定为 `none`
- 网络范围：仅 Stellar
- 审计范围：`src/`、`demo/` 与根目录 `index.html`；独立 `preview/` 页面是静态设计参考板，有意不纳入运行时样式检查
- 当前审计快照：285/335 个 Token 已被消费（85.1%）；未声明引用 0；样式问题 0；旧主题问题 0。

三层迁移会有意扩大公开 Token 清单，因此覆盖率低于此前的 115 个 Token 快照。这不表示视觉或引用质量下降。`design-system/tokens.css` 中的 Primitive、Semantic 别名是兼容桥接，未消费契约则为后续组件迁移或公开状态覆盖预留，默认不应删除。

即使当前色值相同或视觉相近，品牌、成功、交易/请求失败、输入校验错误、上涨、下跌、警告和高风险也必须保持独立语义。

协议紫以 `--Fresnica-accent-purple-*` 为权威名称。原 `--Fresnica-secondary-*` 兼容别名已在 2.0.0 清理中删除。

`--Fresnica-shadow-base` 是正式支持的“明确无投影”契约。原 `--Fresnica-shadow-sm` 与 `--Fresnica-shadow-lg` 兼容别名已在 2.0.0 清理中删除。

即使当前组件没有使用每一个变体，语义颜色的 `hover` 与 `active` 仍作为公开交互契约保留。它们不是基础色的冗余副本，并且必须继续遵守各自的金融语义边界。

`--Fresnica-surface-lowest` 作为应用外壳或全屏画布背景的公开预留契约继续保留。当前没有内部组件消费者是有意为之，不构成弃用理由；组件仍须使用与自身层级匹配的组件表面 Token。

以下同值 Token 属于有意保留的语义重复，不得合并：主色/成功色（浅色成功色与深色主色均为 `#00CA8A`）、失败色/校验错误色（交易/请求失败与输入校验错误是不同语义），以及上涨/下跌与成功/失败之间的方向和状态角色。它们独立维护，以便未来调整视觉值时仍能保持各自含义。

## 允许保留原始值的情况

只有以下已评审位置可以直接出现颜色、尺寸或字体名称：

1. `src/styles/variables.less` 中的 Token 定义，以及 `src/styles/themes/default.less` 中的深色主题覆盖值。
2. 为说明具体 Token 数值而展示的代码示例，例如 Color 页面和 HomePage 的主题代码片段。这些字符串不参与界面样式。
3. 品牌图片、Logo 以及位图/SVG 资源内部的数据。
4. 无法表达为可复用语义刻度的组件几何值，例如 `50%` 圆形、视口计算、媒体固有尺寸和一次性图标对齐值。
5. 专门验证使用者传入行内样式的测试数据。
6. 没有合适 Fresnica Token 的第三方或浏览器必需关键字与尺寸。
7. Demo 专用的布局断点、网格最小宽度、Token 色板尺寸和序号标记几何值；这些值若强行引入全局刻度会降低示例还原度，却不会形成可复用的组件契约。

组件代码中的语法高亮颜色不属于原始值例外，应使用专用的 `--Fresnica-code-*` Token。遮罩透明度应使用 `--Fresnica-mask-bg`、`--Fresnica-mask-bg-subtle` 或 `--Fresnica-mask-bg-strong`。

## 不允许的情况

- 组件或 Demo 的实际界面样式已有语义 Token，却继续直接写原始颜色。
- 仅因为当前色值相同，就使用另一种金融语义角色代替正确角色。
- 普通图标、元数据、复制/Max、方向切换、预计数值、完成状态或金融上涨在没有主操作/选中语义时使用品牌主色 Token。
- 除 `@font-face` 声明和文档示例字符串外，直接写 Roboto/Noto 字体栈。
- 禁用控件使用绿色描边或绿色文字。
- 只适合浅色主题、无法适配深色主题的白色表面。

以后增加新例外时，必须在评审中说明文件位置、用途、负责人和未来移除条件。

## 已复核的排版与几何队列

审计报告中的排版和几何队列已按下表复核。这些值继续作为组件级例外保留；只有同一语义角色被其他组件族复用时，才考虑新增公开 Token。

| 范围 | 当前值 | 保留原因 | 重新评审条件 |
| --- | --- | --- | --- |
| 图标/控件行盒 | `line-height: 0`、`1`、固定 `24px` | 消除行内图片基线空隙，或让紧凑纯图标控件和选择器单元格垂直居中。 | 统一的图标控件基础组件替代局部几何规则。 |
| 紧凑标签和内容行 | `1.25`、`1.3`、`1.4`、`1.45`、`1.5`、`1.6`、`1.7`、`1.8` | 用于列表、浮层、辅助文字和文档内容；直接替换成全局 `1.5715` 会改变组件实测高度。 | 两个或更多组件族采用指标完全一致的命名文字角色。 |
| 展示数字和标题字距 | 负 `em`/像素字距 | 用于大额余额、Modal 标题、Title 标题和交易摘要的光学校正。 | 批准新增命名明确的展示/标题排版 Token。 |
| 紧凑控件字距 | `0.01em`、`0.02em`、`1px` | 提升短标签、选择器数值和状态文字可读性，不属于布局元素间距。 | 同一角色在完整控件集合中实现统一。 |
| 微调对齐偏移 | `2px`、`4px`、`7px`、`22px`、`30px`、`-6px` | 用于选择器单元格、校验标记、Switch 标签/滑块、通知标记、钱包辅助信息和字体回退的局部光学对齐。 | 相关组件几何或内置字体发生变化。 |
| Modal 内容内边距 | 底部 `20px` | 保留 16px 与 24px 间距档位之间经过测量的内容/操作节奏。 | Modal 结构重新设计，或批准可复用的 20px 间距档位。 |

负责人：Fresnica UI 维护者。移除条件：只有现有 Token 能精确保持渲染几何，或经评审新增了可复用语义 Token 时，才替换这些例外。例外不得包含原始颜色、阴影或金融语义替代。

## 可重复执行的审计

运行 `npm run audit:tokens` 可报告 Token 覆盖率、未声明引用、样式中的原始颜色/投影、原始字体声明、原始间距/圆角声明以及旧主题关键词。该命令只读执行：未使用的公开契约只会列出供评审，不会自动删除。字体与几何值属于人工复核队列，不直接导致 CI 失败，因为其中可能包含已记录的合法组件专用尺寸。

## 已评审的未消费契约

审计现在会对所有未直接消费的公共契约进行分类：

- 明确预留的状态契约：hover/active 变体，以及 `surface-lowest` 应用外壳画布契约。
- 保留的兼容契约：`--Fresnica-primary-color-*`、`--Fresnica-text-color-*`、旧 accent/background 名称和反色状态名称等旧运行时变量。
- 保留的 Primitive 桥接契约：向三层 Token 体系提供原始尺度的 `--Fresnica-primitive-*` 别名。
- 预留的 Semantic 契约：当前还没有组件场景的语义角色，例如 gain/risk 容器和次级背景。
- 预留的 Component 契约：例如 Card 阴影，为未来明确的组件变体保留。

这些分类是评审结论，不是删除建议。当组件确实需要某个语义角色时，可以将契约升级为实际使用；在此之前保持兼容并记录用途。审计应显示未分类未消费契约为 0。
